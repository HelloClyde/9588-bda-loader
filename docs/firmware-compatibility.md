# 固件兼容性

BDA Loader 不依赖单一固定入口地址。启动目标 BDA 前，它会从当前 BDA 返回地址反推
path-loader 入口，并验证完整的函数序言、参数保存、`0x81c00020` 装载、`jalr`、
返回分支和 cache barrier。只有全部匹配才会修改外层返回地址。

9688 恢复包的 `C100knl.bin` 与 `kj409688.bin` 在原始内核前多出 64-byte 包装头；
去除该包装头后，分别与 4730、4740 底层升级目录中的 `C100.bin` 一致。Loader 在
真机内存中看到的是解包后的内核地址，因此运行时 profile 使用上表中的地址。

## 本地复核

仓库提供只读验证工具，同时接受原始内核和带 64-byte 包装头的内核：

```powershell
python tools/verify_firmware_profiles.py `
  "D:\Downloads\9688V2.32SD卡一键恢复系统\底层升级4730\C100.bin" `
  "D:\Downloads\9688V2.32SD卡一键恢复系统\底层升级4740\C100.bin"
```

工具只输出哈希、识别结果和入口信息，不会修改或复制固件。仓库不提供固件下载。

## 验证等级

- **静态验证通过**：恢复包中的机器码、调用 ABI、寄存器保存和 cache barrier 已逐项
  对照，Loader 可以识别该 profile；仍建议用诊断版完成首次真机验证。
- **真机验证通过**：已在对应芯片真机上完成 Loader 启动目标 BDA 的动态测试。

9688 首次真机验证后，请保留 `A:\BDALOAD.LOG`。成功调度时应看到
`FIRMWARE_PROFILE=9688-JZ4730` 或 `FIRMWARE_PROFILE=9688-JZ4740`，以及
`DEFER_READY_RETURN_NORMALLY`。
